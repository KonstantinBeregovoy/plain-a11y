# TASK-6: Подготовка к публикации

Цель: репозиторий и пакет готовы к отправке в Chrome Web Store.

## Сделать
1. README.md: что делает расширение, как установить из исходников, архитектура и почему выбраны axe-core и MV3, ограничения (автоматика находит не все проблемы).
2. PRIVACY.md: расширение ничего не собирает и не отправляет, настройки хранятся локально.
3. store/listing.md: краткое и полное описание, формулировка единственной цели, обоснование каждого permission.
4. Иконки 16, 48 и 128 px: простые, сгенерированные скриптом из SVG.
5. Скрипт npm run zip, который собирает пакет для загрузки.
6. Проверить, что в пакете нет удалённо загружаемого кода и лишних permissions.

## Критерии приёмки
- Все проверки прошлых этапов проходят.
- npm run zip создаёт архив, расширение из него загружается без ошибок.
- В manifest только activeTab, scripting, storage.
- Скриншоты 1280x800 агент не делает, он оставляет в store/listing.md список нужных кадров.

## Вопросы и решения агента

1. Иконки нужно генерировать скриптом из SVG, а растеризатора в стеке нет. Выбрано самое простое: dev-зависимость `sharp`, скрипт `scripts/make-icons.mjs`, исходник `scripts/icon.svg`, результат в `src/public/icon/`. Для этого появились папки `scripts` и `src/public`, а в `wxt.config.ts` задан `publicDir: 'src/public'`. Если папки сверх структуры из SPEC.md нежелательны, скажите, куда их перенести.
2. Для теста ограничений пакета (`tests/package.test.ts`) добавлена dev-зависимость `@types/node` (только типы).
3. При проверке пакета на удалённо загружаемый код найдены два источника сетевых запросов: предзагрузка стилей и медиа в axe-core (`preload`, скачивает ресурсы страницы) и полифил предзагрузки модулей Vite. Оба отключены (`axe.run(document, { preload: false })` и `build.modulePreload.polyfill: false`), потому что SPEC запрещает сетевые запросы. Побочный эффект: для страниц с кросс-доменными таблицами стилей часть правил, которым нужны эти стили, может срабатывать менее полно. Если полнота важнее, `preload` можно включить обратно, но тогда надо поправить PRIVACY.md.
4. В PRIVACY.md нет контактной почты и ссылки на репозиторий, потому что их нет в задании. Для формы магазина нужна публичная ссылка на политику: её надо добавить после публикации репозитория.
5. Скриншоты 1280×800 не делались, список кадров лежит в `store/listing.md`, как требует задание.
