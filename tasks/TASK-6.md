# TASK-6: Preparing for publication

Goal: the repository and the package are ready to be sent to the Chrome Web Store.

## Steps
1. README.md: what the extension does, how to install from source, the architecture and why axe-core and MV3 were chosen, the limits (automation does not find every problem).
2. PRIVACY.md: the extension collects and sends nothing, settings are stored locally.
3. store/listing.md: the short and full descriptions, the single-purpose statement, the justification of each permission.
4. Icons of 16, 48 and 128 px: simple, generated by a script from an SVG.
5. An npm run zip script that builds the package for upload.
6. Check that the package has no remotely loaded code and no extra permissions.

## Acceptance criteria
- All checks from earlier stages pass.
- npm run zip creates an archive, and the extension loads from it without errors.
- The manifest has only activeTab, scripting, storage.
- The agent does not make 1280x800 screenshots; it leaves a list of the needed frames in store/listing.md.

## Questions and agent decisions

1. The icons must be generated by a script from an SVG, and the stack has no rasterizer. The simplest choice: the dev dependency `sharp`, the script `scripts/make-icons.mjs`, the source `scripts/icon.svg`, the result in `src/public/icon/`. This added the folders `scripts` and `src/public`, and `wxt.config.ts` sets `publicDir: 'src/public'`. If folders beyond the structure in SPEC.md are not wanted, say where to move them.
2. For the package limits test (`tests/package.test.ts`) the dev dependency `@types/node` was added (types only).
3. Checking the package for remotely loaded code found two sources of network requests: the preloading of styles and media in axe-core (`preload`, which downloads the page's resources) and the module preload polyfill of Vite. Both are switched off (`axe.run(document, { preload: false })` and `build.modulePreload.polyfill: false`), because SPEC forbids network requests. A side effect: on pages with cross-origin stylesheets, some rules that need those styles may work less fully. If completeness matters more, `preload` can be switched back on, but then PRIVACY.md must be corrected.
4. PRIVACY.md has no contact email and no link to the repository, because the task does not have them. The store form needs a public link to the policy: it must be added after the repository is published.
5. Screenshots of 1280×800 were not made; the list of frames is in `store/listing.md`, as the task requires.
