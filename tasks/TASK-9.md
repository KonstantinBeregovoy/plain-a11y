# TASK-9: Правило target-size

Цель: проверять размер кликабельных целей по WCAG 2.2 AA. В axe это правило выключено по умолчанию.

## Сделать
1. Включить правило target-size при запуске axe (опция rules в вызове axe.run).
2. Добавить запись в словарь: простое название, кого касается, как исправить, роль design. Тексты по правилам TASK-2.
3. Добавить в tests/fixtures/basic.html маленькую кнопку (с aria-label, чтобы не сработало button-name), которая нарушает правило.

## Критерии приёмки
- Все проверки прошлых этапов проходят.
- Unit-тест: в запуске axe правило target-size включено, а список остальных опций не изменился.
- Unit-тест словаря покрывает новую запись (все поля, id существует в axe.getRules()).
- На обновлённом basic.html агент в Chromium видит target-size вместе с прежними четырьмя правилами.

## Не делать
Другие выключенные правила.

## Результаты и отклонения агента

1. Параметры запуска axe вынесены в src/content/axeOptions.ts (AXE_RUN_OPTIONS: preload false и правило target-size включено). Так их можно проверить тестом, а content script использует одну константу.
2. Добавлена запись словаря для target-size (роль design). Тексты проходят существующие тесты простоты.
3. В tests/fixtures/basic.html добавлены две крошечные кнопки (12x12 px, с aria-label) рядом друг с другом. Одной кнопки недостаточно: по правилу размер цели не проверяется, если вокруг неё есть свободный круг диаметром 24 px, то есть одиночная маленькая кнопка проходит. Теперь на basic.html 5 проблем вместо 4: image-alt, label, color-contrast, link-name, target-size (2 элемента).
4. Тесты: tests/axeOptions.test.ts (3 теста), запись словаря target-size в tests/dictionary.test.ts, проверка в tests/package.test.ts обновлена под AXE_RUN_OPTIONS. Всего 62 теста.
5. В Chromium: все 5 правил найдены, у target-size корректное описание, подсветка обводит обе кнопки, после снятия разметка совпадает с исходной, на чистой странице с кнопкой 40x40 px нарушений нет. Аудит axe по 14 состояниям popup: 0 нарушений.
