# TASK-14: Раздел «Needs manual review»

Цель: показывать случаи, которые axe не смог решить сам (результаты incomplete), отдельным разделом, чтобы пустой отчёт не звучал увереннее, чем есть на самом деле.

## Сделать
1. Content script возвращает кроме violations ещё и incomplete в том же компактном формате.
2. Popup показывает раздел «Needs manual review» под основным списком: те же названия и тексты из словаря, пометка, что axe не смог решить сам и нужен человек. Эти случаи не входят в счётчик «Issues found».
3. Кнопка «Show on page» работает и для этих пунктов (подсветка и прокрутка к первому элементу).
4. Markdown-отчёт содержит отдельную секцию «Needs manual review». Сообщение для пустого результата упоминает число таких пунктов, если они есть.
5. Правила, у которых нет записи в словаре, показываются с текстом axe, как и в основном списке.

## Критерии приёмки
- Все проверки прошлых этапов проходят.
- Unit-тесты: разбор incomplete, раздел в отчёте, пустой результат с пунктами на проверку и без них.
- Тест axe на popup включает состояние с разделом «Needs manual review» без нарушений.
- Агент проверяет в Chromium страницу, на которой axe выдаёт incomplete (например, текст на фоновой картинке).

## Не делать
Ручной чек-лист с отметками выполнения, сохранение состояния пунктов.

## Результаты агента

1. Content script возвращает кроме нарушений ещё review: результаты incomplete в том же компактном формате (CheckResponse.review). Новая функция groupByRole группирует их по ролям, функция toMarkdown получила необязательный третий параметр review.
2. Popup: после основного списка раздел «Needs manual review: N» с пояснением «The automated check could not decide these on its own. A person needs to look at them.», пункты сгруппированы по ролям (Design, Content, Code) с теми же текстами из словаря. Эти пункты не входят в «Issues found». Итоговая строка: «Issues found: 4 Needs manual review: 2.» или «No issues found. Needs manual review: 2.». Фильтр роли действует и на раздел. Если проблем нет, но есть пункты на проверку, фильтр и раздел всё равно показываются.
3. Подсветка работает и для этих пунктов. Одно и то же правило может быть и в нарушениях, и в ручной проверке (например, color-contrast для разных элементов), поэтому ключ подсветки теперь с префиксом review: и нажатие в одном списке не нажимает кнопку в другом. Для этого useHighlight.toggle принимает необязательный ключ.
4. Markdown: секция «## Needs manual review» после секций ролей, пункты вида «- [ ] Design: название. If confirmed, how to fix: …». Для пустого результата с пунктами на проверку: «The automated check found no issues, but N items need a manual review (listed below). It covers only part of…». Без пунктов на проверку старый текст и снапшот не изменились.
5. Правила без записи в словаре показываются с текстом axe, как и в основном списке (проверено тестом отчёта).
6. Добавлена тестовая страница tests/fixtures/review.html (текст на картинке и видео без явных субтитров), на ней axe выдаёт два пункта на проверку: color-contrast и video-caption.
7. Тесты: 90, все проходят (groupByRole, секция и пустой результат в отчёте, четыре новых теста popup: пункты на проверку вместе с проблемами, только пункты на проверку, независимая подсветка копии правила, фильтр роли). Тесты axe на popup охватывают два новых состояния, 0 нарушений.
8. Проверено в Chromium: на review.html итог «No issues found. Needs manual review: 2.», два пункта в ролях Design и Content, подсветка обводит абзац, после снятия разметка совпадает с исходной, отчёт содержит новую секцию. Аудит axe в обеих схемах для новых состояний и прежние 14 состояний: 0 нарушений.
9. В README и в docs/a11y-checklist.md добавлено описание нового раздела и состояний.

### Замечание

В разделе пунктам отведена подпись «How to fix», как у обычных проблем, хотя проблема ещё не подтверждена. Это снято пояснением в начале раздела, а в Markdown используется формулировка «If confirmed, how to fix». Если хотите другую формулировку в popup, это правка в одном компоненте (src/popup/IssueGroups.tsx).
